# 1. Project Overview — โปรเจกต์ของเราคืออะไร?

เราจะพัฒนาระบบ **SENTINEL AI** ซึ่งเป็นระบบจำลองศูนย์ปฏิบัติการรักษาความปลอดภัยทางไซเบอร์ หรือ Security Operations Center (SOC) ที่ใช้ปัญญาประดิษฐ์เป็นแกนหลักในการวิเคราะห์เหตุการณ์และวางแผนตอบสนองต่อภัยคุกคาม

แนวคิดคือการสร้าง **AI Security Engineer** ที่สามารถทำงานร่วมกับระบบตรวจจับภัยคุกคามได้จริง

โดยปกติเมื่อระบบเครือข่ายเกิดเหตุการณ์ผิดปกติ เช่น มีคนพยายาม Login ซ้ำ ๆ หรือมีการสแกนพอร์ต ผู้ดูแลระบบจะต้องตรวจสอบ Logs เอง วิเคราะห์ว่าเป็นการโจมตีหรือไม่ และตัดสินใจว่าควรป้องกันอย่างไร

SENTINEL AI จะช่วยทำงานในกระบวนการดังกล่าว

### ความสามารถหลัก

1. ตรวจสอบ Network Logs และ Security Events
2. ตรวจจับพฤติกรรมที่อาจเป็นภัยคุกคาม
3. ใช้ Local AI วิเคราะห์หลักฐานและสาเหตุของเหตุการณ์
4. ใช้ AI Agent เรียกเครื่องมือเพื่อสืบค้นข้อมูลเพิ่มเติม
5. ให้ AI เสนอแนวทางป้องกัน
6. ให้ผู้ดูแลอนุมัติหรือปฏิเสธ Action
7. ดำเนินการป้องกันผ่าน Firewall Simulator
8. ตรวจสอบว่าการป้องกันสำเร็จหรือไม่
9. บันทึกประวัติและสร้างรายงานเหตุการณ์
10. แสดงกระบวนการทั้งหมดผ่าน Real-time Dashboard

**สิ่งที่แตกต่างจาก Chatbot ทั่วไป คือ AI สามารถเลือกใช้เครื่องมือและทำงานเป็น Workflow ได้ ไม่ใช่เพียงรับ Prompt แล้วตอบข้อความกลับมา**

# 2. Problem Statement — ปัญหาที่ต้องการแก้ไข

ระบบรักษาความปลอดภัยเครือข่ายในองค์กรต้องรับข้อมูลจำนวนมาก เช่น

- Authentication Logs
- Firewall Logs
- Network Connection Logs
- Server Logs
- Web Application Logs
- Security Alerts

ข้อมูลเหล่านี้มีประโยชน์ แต่ผู้ดูแลระบบอาจต้องใช้เวลาในการตรวจสอบและเชื่อมโยงเหตุการณ์

ตัวอย่างเช่น

```text
12:30:01 Failed SSH Login from 192.0.2.25
12:30:02 Failed SSH Login from 192.0.2.25
12:30:03 Failed SSH Login from 192.0.2.25
12:30:04 Failed SSH Login from 192.0.2.25
...
```

หากมี Logs หลายพันรายการ ผู้ดูแลระบบอาจไม่สามารถตรวจสอบทุกเหตุการณ์ได้ทันที

### ปัญหาหลัก

**1. Information Overload**

มี Logs จำนวนมาก ทำให้ตรวจสอบเหตุการณ์ที่สำคัญได้ยาก

**2. Manual Investigation**

ผู้ดูแลต้องค้นหาและวิเคราะห์หลักฐานจากหลายแหล่งด้วยตัวเอง

**3. Delayed Incident Response**

การวิเคราะห์และดำเนินการตอบสนองอาจใช้เวลานาน

**4. Lack of Explainability**

ระบบแจ้งเตือนทั่วไปอาจไม่ได้อธิบายเหตุผลหรือเชื่อมโยงหลักฐานอย่างละเอียด

**5. Complex Security Operations**

การตรวจสอบข้อมูล สร้างแผนป้องกัน และดำเนินการผ่านเครื่องมือหลายส่วนมีความซับซ้อน

### แนวทางแก้ไข

ใช้ Agentic AI ทำหน้าที่ช่วยสืบสวน วิเคราะห์ และเสนอการตอบสนอง โดยมีระบบตรวจจับแบบกำหนดกฎเป็นด่านแรก และมีมนุษย์ควบคุมการดำเนินการที่มีผลกระทบต่อระบบ

# 6. ทำไมถึงเลือก Local AI?

แทนที่จะเรียก OpenAI API หรือ Gemini API เราจะใช้โมเดลที่ดาวน์โหลดมารันบนเครื่องตัวเอง

### ข้อดี

- ไม่ต้องจ่ายค่า API ตามจำนวน Token
- ไม่ต้องส่ง Logs ไปยังผู้ให้บริการ Cloud AI
- รองรับการทำงาน Offline
- สามารถควบคุมโมเดลและการตั้งค่าเองได้
- เหมาะกับการศึกษา Local AI Deployment
- สามารถทดสอบ Performance บน GPU ได้จริง

### ข้อจำกัด

- ต้องใช้ RAM และ VRAM
- AI ขนาดเล็กอาจวิเคราะห์ผิดพลาด
- มีข้อจำกัดด้าน Context Length
- Tool Calling อาจไม่ถูกต้องทุกครั้ง
- ต้องออกแบบ Error Handling และ Validation

ด้วยเหตุนี้เราจะไม่ให้ LLM เป็นตัวตัดสินใจทุกอย่าง แต่จะแยก Detection Engine และ Policy Validation ออกจาก AI

# 8. End-to-End Workflow

ระบบทำงานตามกระบวนการ

**Observe → Detect → Investigate → Reason → Plan → Approve → Defend → Verify**

### 1. Observe

ระบบรับ Security Events จาก Log Simulator หรือแหล่งข้อมูลที่รองรับ

### 2. Detect

Detection Engine วิเคราะห์รูปแบบ Logs และสร้าง Alert เมื่อพบเหตุการณ์ผิดปกติ

### 3. Investigate

AI Agent เรียกเครื่องมือเพื่อรวบรวมข้อมูลเพิ่มเติม

### 4. Reason

LLM วิเคราะห์หลักฐานและจำแนกประเภทเหตุการณ์

### 5. Plan

AI เสนอ Defense Action พร้อมเหตุผลประกอบ

### 6. Approve

ผู้ดูแลตรวจสอบแผนและอนุมัติหรือปฏิเสธ

### 7. Defend

Backend ดำเนินการตาม Action ที่อนุมัติผ่าน Firewall Simulator

### 8. Verify

ระบบทดสอบผลการป้องกันและบันทึก Incident Report

# 9. Local Agentic AI Engine

นี่คือหัวใจสำคัญที่สุดของงาน

เราไม่ได้ใช้ AI แบบ Chat Completion อย่างเดียว แต่จะให้โมเดลสามารถเรียกใช้ Tools เพื่อค้นหาข้อมูลและดำเนินงานตามขั้นตอน

## 9.1 Agent Architecture

ใช้ LangGraph สร้าง Workflow ที่ประกอบด้วย

- Investigation Node
- Threat Analysis Node
- Defense Planning Node
- Approval Node
- Execution Node
- Verification Node

บทบาทเหล่านี้สามารถใช้ LLM โมเดลเดียวกันตามลำดับ เพื่อลดการใช้ VRAM

## 9.2 Investigation Agent

หน้าที่:

- ตรวจสอบ Incident
- ดึง Logs ที่เกี่ยวข้อง
- วิเคราะห์ IP Activity
- ค้นหาเหตุการณ์ที่เชื่อมโยงกัน
- ตรวจสอบสถานะ Firewall
- ส่ง Evidence ให้ Analysis Node

ตัวอย่าง Tools:

```python
get_incident_logs(incident_id)

get_ip_activity(ip_address)

get_failed_login_count(ip_address)

get_related_incidents(ip_address)

get_firewall_status(ip_address)
```

## 9.3 Threat Analysis Agent

AI วิเคราะห์

- ประเภทภัยคุกคาม
- หลักฐานประกอบ
- ระดับความเสี่ยง
- ผลกระทบที่อาจเกิดขึ้น
- ความน่าเชื่อถือของข้อสรุป
- ข้อมูลเพิ่มเติมที่ควรตรวจสอบ

ตัวอย่าง Output:

```json
{
  "incident_id": "INC-0001",
  "threat_type": "SSH_BRUTE_FORCE",
  "severity": "HIGH",
  "source_ip": "192.0.2.25",
  "evidence": [
    "35 failed logins within 60 seconds",
    "Repeated attempts from same source"
  ],
  "recommended_action": "TEMP_BLOCK_IP",
  "requires_approval": true
}
```

## 9.4 Defense Planning Agent

เสนอ Action ที่อนุญาต เช่น

| Action | ความหมาย |
|---|---|
| `MONITOR` | เฝ้าติดตาม |
| `INVESTIGATE` | ตรวจสอบเพิ่มเติม |
| `BLOCK_IP` | บล็อก IP |
| `TEMP_BLOCK_IP` | บล็อกชั่วคราว |
| `NO_ACTION` | ไม่ดำเนินการ |

ทุก Action ต้องผ่าน Policy Validator ก่อนส่งให้ผู้ดูแลพิจารณา

## 9.5 Execution & Verification

AI สร้างแผน แต่ Backend เป็นผู้ดำเนินการจริงหลังอนุมัติ

ขั้นตอน:

1. ตรวจสอบ Action Schema
2. ตรวจสอบ IP และสิทธิ์
3. ตรวจสอบ Protected Targets
4. ตรวจสอบ Approval
5. ดำเนินการใน Firewall Simulator
6. ทดสอบ Packet ใหม่
7. บันทึก Verification Result

- Source IP Activity
- Threat Classification
- Evidence
- AI Recommendation
- Analysis Duration

## Feature 3 — Live Agent Workflow

แสดงการทำงาน Agent เป็น Workflow Diagram

```text
Threat Detected
      ↓
Collecting Evidence
      ↓
AI Threat Analysis
      ↓
Defense Planning
      ↓
Policy Validation
      ↓
```

- Waiting

คลิกดูรายละเอียดได้ เช่น Tool Input/Output และ Execution Time

**นี่คือฟีเจอร์ Highlight สำคัญ เพราะแสดงให้เห็นว่า AI มีการใช้ Tools และทำงานเป็นขั้นตอนจริง**

## Feature 4 — Explainable AI Decisions

แสดงเหตุผลและหลักฐานที่ AI ใช้ประกอบข้อเสนอ

ตัวอย่าง

```text
Threat: SSH Brute Force
Severity: HIGH

Evidence:
- Failed Login 35 times
- Same source IP
- Within 60 seconds

Recommendation:
Temporarily block source IP

Reason:
Repeated authentication failures
```

## Feature 5 — Human Approval

เมื่อ AI เสนอ Action ระบบจะแสดง

```text
AI DEFENSE PROPOSAL

Target IP: 192.0.2.25
Action: TEMP_BLOCK_IP
Duration: 10 minutes

[ APPROVE ]  [ REJECT ]
```

หาก Reject ระบบจะไม่ดำเนินการ

หาก Approve Backend จะตรวจสอบอีกครั้งก่อนเรียก Firewall Simulator

## Feature 6 — Firewall Simulator

รองรับ

- Block IP
- Unblock IP
- Temporary Block
- Expiration
- Rule History
- Allow / Deny Packet
- Protected IPs
- Verification

ใช้จำลองการทำงานของ Firewall โดยไม่ต้องแก้ Network ของเครื่องจริง

## Feature 7 — Attack Scenario Simulator

สร้างหน้าเลือกสถานการณ์ทดสอบ

### Scenarios

**Scenario A — SSH Brute Force**

สร้าง Failed Login จำนวนมากจาก IP เดียว

**Scenario B — Port Scanning**

สร้าง Connection Attempts ไปยังพอร์ตจำนวนมาก

**Scenario C — Suspicious Login**

จำลอง Failed Login ต่อเนื่องก่อน Login สำเร็จ

**Scenario D — Normal Traffic**

จำลองการใช้งานปกติเพื่อทดสอบ False Positive

**Scenario E — Traffic Anomaly (เสริม)**

สร้างจำนวน Connection เพิ่มขึ้นผิดปกติ

ทุก Scenario ต้องสร้าง Events เข้าสู่ Backend จริงผ่าน Pipeline เดียวกัน

## Feature 8 — Before / After Defense

แสดงภาพเปรียบเทียบผลการป้องกัน

ก่อนป้องกัน:

```text
192.0.2.25 → Firewall → Demo Server
                    ALLOWED
```

หลังป้องกัน:

```text
192.0.2.25 → Firewall → BLOCKED
```

พร้อม Counter แสดง Allowed และ Denied Connections

## Feature 9 — Incident Timeline

แสดงลำดับเวลา

```text
12:30:00 Attack Simulation Started
12:30:05 Threat Detected
12:30:10 AI Investigation Started
12:30:17 Defense Plan Generated
12:30:25 Admin Approved
12:30:26 Firewall Rule Applied
12:30:27 Verification Passed
```

ข้อมูลทั้งหมดดึงจาก Execution Records จริง

## Feature 10 — AI Security Assistant (Optional)

ช่องแชตเพื่อถามข้อมูลเกี่ยวกับ Incidents

ตัวอย่าง

- ตอนนี้มีภัยคุกคามอะไร?
- สรุป Incident ล่าสุด
- ทำไม IP นี้ถึงถูกบล็อก?
- แสดงเหตุการณ์ที่มี Severity สูง
- อธิบาย Brute Force Attack

AI ต้องเรียก Tool เพื่ออ่านข้อมูล Database และตอบจากหลักฐานที่มี

## Feature 11 — Local RAG Knowledge Base (Optional)

ให้ AI ค้นหาข้อมูลจากเอกสาร Cybersecurity ที่จัดเตรียมไว้

เช่น

- Incident Response Playbooks
- Security Best Practices
- Threat Classification Guidelines
- MITRE ATT&CK Reference Data

ใช้ Local Embeddings และ ChromaDB สำหรับค้นหาข้อมูลภายในเครื่อง

| POST | `/api/defense/{id}/approve` | Approve Action |
| POST | `/api/defense/{id}/reject` | Reject Action |
| GET | `/api/firewall/rules` | Firewall Rules |
| POST | `/api/simulator/start` | Start Scenario |
| POST | `/api/simulator/stop` | Stop Scenario |
| GET | `/api/reports` | Incident Reports |
| WebSocket | `/ws/events` | Real-time Events |

### Step 1 — เปิดระบบ

ระบบตรวจพบ Failed Login จำนวนมากและสร้าง Incident

### Step 4 — AI Investigation

### Step 5 — AI Analysis

แสดงประเภทภัยคุกคาม หลักฐาน และระดับความเสี่ยง

### Step 6 — Defense Planning

AI เสนอ Temporary Block IP

### Step 7 — Human Approval

ผู้ดูแลกด Approve

### Step 8 — Firewall Execution

Firewall Simulator เพิ่ม IP ลง Blocklist

# 23. Final Project Vision

หัวใจสำคัญของโปรเจกต์คือการประยุกต์ **Local Agentic AI** ให้เป็นตัวเชื่อมระหว่างข้อมูล Security และเครื่องมือป้องกันภัยคุกคาม

ระบบจะต้องทำให้เห็นว่า AI ไม่ใช่เพียงเครื่องมือถามตอบ แต่สามารถเป็นส่วนหนึ่งของ Software System ที่มีความสามารถในการวิเคราะห์ วางแผน และช่วยดำเนินงานได้จริง
