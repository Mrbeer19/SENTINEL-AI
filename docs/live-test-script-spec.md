# สเปกสคริปต์ทดสอบสด: ยิงจริง → โดนบล็อก → ปลดบล็อก → ยิงซ้ำ

สคริปต์ใหม่ `scripts/vps_live_test.py` รันบน Mac (เครื่องผู้ทดสอบ) ใช้ตอนซ้อมและสาธิตกับ VPS จริง
ทำงานแบบถาม-ตอบใน Terminal เป็นภาษาไทย

## สิ่งที่ระบบบน VPS ทำอยู่แล้ว (สคริปต์ไม่ต้องแตะ)

- VPS เดียวดูทุกเว็บที่ผ่าน Caddy + SSH + ทุกพอร์ต ตอนนี้มีเว็บ `rangsitnanmai.tntstudio.tech` (ไม่มีระบบ login มีแต่ GET)
- พออนุมัติบล็อกบน dashboard แล้ว **IP ผู้โจมตีจะได้ HTTP 403 จากทุกเว็บบน VPS** (บล็อกที่ Caddy เท่านั้น)
  SSH และพอร์ตอื่นไม่ถูกบล็อก ดังนั้นหลักฐานว่า "โดนบล็อก" ของทุกการทดสอบคือ **เว็บตอบ 403 กับเครื่องนี้**
- ตั้งไว้ให้ปลดบล็อกด้วยมือเท่านั้น (admin กดใน dashboard) หลังปลดเว็บจะกลับมาตอบ 200
- dashboard: `https://sentinel.<ip-ใช้ขีด>.sslip.io` (เช่น `sentinel.179-197-254-226.sslip.io`)

## เกณฑ์ของกฎ (ภายใน 60 วินาที ต่อ IP)

| การทดสอบ | สิ่งที่สคริปต์ทำ | incident ที่ควรเกิด | AI วิเคราะห์ (เห็นภาพ 3D) |
|---|---|---|---|
| 1. Honeypot | `GET /backup.sql` 1 ครั้ง | HONEYPOT | ไม่ (กฎเฉพาะทาง) |
| 2. Web scan | GET path ที่ไม่มีจริง 12 path เช่น `/.env` `/wp-admin/` `/phpmyadmin/` `/admin.php` `/.git/config` + สุ่ม | WEB_SCAN (404 ≥ 10 หรือ path สแกนเนอร์ ≥ 3) | ไม่ |
| 3. HTTP flood | `GET /` 320 ครั้งใน ~40 วิ (พร้อมกันไม่เกิน 5) | HTTP_FLOOD (≥ 300) | ไม่ |
| 4. SSH เดารหัส | ล็อกอิน SSH ผิด 6 ครั้ง ห่างกัน ~2 วิ | SSH_BRUTE_FORCE (≥ 5) | **ใช่** |
| 5. Port scan | TCP connect 12 พอร์ตที่ต่างกัน (ไม่ใช่ 80/443) เช่น 21 23 25 110 143 445 3306 3389 5432 6379 8080 8443 timeout 1 วิ | PORT_SCAN (≥ 8 พอร์ต) | **ใช่** |
| 6. Connection flood (ตัวเลือก ขึ้นคำเตือนก่อน) | TCP connect พอร์ต 22 แล้วปิดทันที 110 ครั้งใน ~50 วิ | TRAFFIC_ANOMALY (≥ 100) | **ใช่** |

หมายเหตุ
- พอร์ต 80/443 ไม่นับเป็นการเคาะพอร์ต (เป็นคนเข้าเว็บ ดูจาก log ของ Caddy) อย่าใช้สองพอร์ตนี้ในข้อ 5 และ 6
- ไฟล์ static (`.css` `.js` รูป ฟอนต์) ไม่นับในข้อ 3 ให้ยิง `/` เท่านั้น
- ข้อ 4 ใช้ **ชื่อผู้ใช้ที่ไม่มีจริง** สุ่มทุกครั้ง เช่น `sentinel-test-ab12` กับรหัสสุ่ม ห้ามใช้ `root` หรือบัญชีจริง ใช้ `paramiko` ถ้ามี (ติดตั้งใน venv) ถ้าไม่มีให้บอกวิธีติดตั้งแล้วข้ามข้อนี้ ห้ามขอรหัสจริงจากผู้ใช้
- ข้อ 1–3 เป็นภัยเว็บที่ตรวจด้วยกฎ ไม่ผ่าน AI ถ้าอยากโชว์ภาพ 3D ของ AI ให้ใช้ข้อ 4–6

## ลำดับการทำงานของสคริปต์

1. ถาม IP ของ VPS (ตรวจว่าเป็น IPv4/IPv6 ถูกรูปแบบ) และชื่อเว็บที่จะใช้ตรวจ (ค่าเริ่มต้น `rangsitnanmai.tntstudio.tech`) แสดงลิงก์ dashboard ที่คำนวณจาก IP
2. preflight
   - หา IP สาธารณะของเครื่องนี้ (เช่น `https://api.ipify.org`) แสดงให้เห็น ถ้าตรงกับ IP ของ VPS ให้หยุด (ห้ามยิงจากตัว VPS เอง ระบบจะไม่นับ)
   - `GET https://<เว็บ>/` ต้องได้ 200 ถ้าได้ 403 แปลว่าเครื่องนี้ถูกบล็อกค้างอยู่ ให้บอกให้ปลดบล็อกใน dashboard ก่อน แล้วรอจนกลับมา 200
3. แสดงเมนูข้อ 1–6 + ออก ให้เลือก ก่อนยิงทุกครั้งให้สรุปว่าจะทำอะไร กี่ครั้ง ไปที่ไหน แล้วถาม y/n
4. ยิงตามข้อที่เลือก แสดงความคืบหน้าทีละบรรทัด (จำนวนที่ส่ง, status ที่ได้, เวลา)
5. **รอผลบล็อก** บอกผู้ใช้ว่า "ไปที่ dashboard → Approvals แล้วกดอนุมัติ" จากนั้นเช็ก `GET https://<เว็บ>/` ทุก 5 วินาที
   แสดงสถานะสด (200 = ยังไม่บล็อก) พอได้ **403** ให้ขึ้นข้อความเด่นว่า **โดนบล็อกแล้ว** พร้อมเวลาที่ใช้ตั้งแต่ยิงจนโดนบล็อก
   รอได้สูงสุด 10 นาที กด Ctrl+C เพื่อยกเลิกการรอแล้วกลับเมนูได้
6. **รอปลดบล็อก** บอกให้ไปกดปลดบล็อกใน dashboard (Protection) แล้วเช็กทุก 5 วินาทีเหมือนเดิม ระหว่างนี้แสดง 403 ไปเรื่อย ๆ
7. พอกลับมาเป็น 200 ให้ **ยิงซ้ำแบบเบา** (`GET /` 3 ครั้ง) แล้วแสดงผล 200 ทั้งหมดเป็นหลักฐานว่า **ปลดบล็อกแล้ว** จากนั้นกลับเมนูเพื่อทดสอบข้ออื่นต่อ
8. ทุกการกระทำบันทึกเป็น JSONL ใน `live-test-<วันเวลา>.jsonl` (เวลา, ข้อทดสอบ, เป้าหมาย, ผล/status) ไว้ทำรายงาน ห้ามบันทึกรหัสผ่านที่สุ่ม

## ข้อห้าม / ความปลอดภัย

- ยิงได้เฉพาะ IP และชื่อเว็บที่ผู้ใช้กรอก ห้ามมีเป้าหมายอื่นในโค้ด
- ห้ามเกินจำนวนในตาราง (เว็บเป็นของเพื่อน ห้ามทำให้ล่ม) ใส่ timeout ทุกคำขอ (5 วิ) และไม่ retry รัว ๆ
- ไม่มี payload โจมตีจริง (ไม่มี SQLi/RCE) แค่ path ที่ไม่มีอยู่
- ไม่แก้อะไรบน VPS ไม่ SSH เข้าไปเป็น admin ไม่เรียก API ของ dashboard (ให้คนกดเอง จะได้เห็นขั้นอนุมัติของ admin)
- เวลาเดโมจริง ควรให้ admin ล้างประวัติก่อนเริ่ม (ข้อมูลที่ยิงตอนซ้อมจะค้างใน dashboard)

## งานโค้ด

- Python 3.9+ ใช้ standard library (`urllib.request`, `socket`, `concurrent.futures`, `ipaddress`, `json`) ส่วน `paramiko` เป็นตัวเลือกสำหรับข้อ 4 เท่านั้น
- แยกฟังก์ชันให้เทสต์ได้: สร้างรายการ path ของข้อ 2, สร้างชื่อผู้ใช้สุ่ม, แปลงผลเช็กสถานะ (200/403/อื่น ๆ/timeout) เป็นข้อความ, ตรวจรูปแบบ IP
- เทสต์ `scripts/test_vps_live_test.py` (unittest) ไม่ยิงเครือข่ายจริง (mock การเชื่อมต่อ)
- เพิ่มหัวข้อวิธีใช้สั้น ๆ ใน `scripts/neo/README.md` (แผนหลักบน VPS)
- commit บน branch ใหม่ `feature/ops/<ชื่อ>-live-test-script` แยกจากงานอื่น ข้อความ commit / PR ไม่มีชื่อเครื่องมือหรือ AI
