## 4. ข้อสรุปสำหรับงานวิจัย

1. r3 ปลอดภัยเท่า r2: FP 0 และ injection 0 ทั้ง 135 เคสบน M5
2. บนข้อมูลที่ r3 ไม่เคยเห็น (v4) ได้ 91% ต่ำกว่าชุดที่ใช้เป็นแนวในการแก้ (v2 100%) → ส่วนหนึ่งของคะแนนที่ขึ้นมาจากการเทรนตามชุดทดสอบ ควรรายงานคู่กันเสมอ
3. จุดอ่อนที่ยังเหลือ 2 แบบ ซ้ำกันทั้ง v3 และ v4: (ก) input ยาวมาก (≥150 พอร์ต) รูปแบบพัง (ข) injection ปริมาณน้อย → ป้ายเพี้ยน + hallucination ในคำอธิบาย
4. ข้อจำกัด: ไม่ได้รัน r2 บน v4 จึงยังสรุปไม่ได้ว่าบนข้อมูลใหม่ r3 ดีกว่า r2 หรือแค่เท่ากัน

## 5. ข้อเสนอ (ยังไม่ได้ทำ)

- prompt (ฝั่ง Beer): เพิ่มขั้น TRAFFIC_ANOMALY (≥100 connection โดยพอร์ตน้อย) ให้ตรงกับกฎ backend
- พอร์ตยาว: แก้ได้สองทาง — เทรนเพิ่ม หรือให้ tool `get_ip_activity` ตัด `ports_touched` เหลือ N ตัวแรก + ส่ง `distinct_ports` เป็นตัวเลข (ฝั่ง backend ทำได้ ต้องตกลงกันก่อนเพราะเปลี่ยน contract)
- ถ้าจะเทรน r4 อย่าใช้ obeto-v4 เป็นแนวทาง เก็บไว้เป็น held-out แล้วทำชุดใหม่อีกชุดหลังเทรน
